# Hyperliquid Radar

Локальный браузерный радар крупных исполнений Hyperliquid. Ключи API не нужны.

## Запуск

Дважды щёлкните `launch.ps1`. Скрипт поднимает локальный сервер на `127.0.0.1:8765` и открывает браузер. Проект не требует Node.js, Python или базы данных.

## Что делает

- подключается к `https://api.hyperliquid.xyz/info` и `wss://api.hyperliquid.xyz/ws`;
- слушает поток `trades` по выбранным активам и показывает адрес покупателя и продавца;
- позволяет добавить до 100 адресов в точный поток `userFills`;
- для точного watchlist показывает `LONG/SHORT` и `ОТКРЫТИЕ/ЗАКРЫТИЕ` из поля `dir` Hyperliquid;
- адрес можно сохранить кнопкой `сохранить` в discovery или вручную вставить в список и нажать `Сохранить адреса`;
- объединяет дробные исполнения по адресу, активу и направлению за заданное окно;
- после каждых 30 новых discovery-адресов проверяет накопленный объём и автоматически добавляет адреса от 100 000 USD в watchlist;
- сохраняет события и настройки в браузерном `localStorage`;
- имеет два режима: полный радар и непрерывный режим «Лучшие трейды» до ручного нажатия «Остановить анализ»;
- отправляет browser notifications при достижении порога и экспортирует Excel-compatible CSV;
- не экспортирует Excel/PnL автоматически после пакета адресов: выгрузка выполняется только кнопками `Excel` и `PnL`;
- сохраняет на рабочий стол `hyperliquid-radar-events-by-usd-*.csv` (сортировка по USD) и `hyperliquid-radar-pnl-by-pnl-*.csv` (сортировка по PnL), включая live-файлы.

Публичный API не содержит единого официального списка китов. Поэтому “discovery” строит наблюдаемый список адресов из live trade-потока. В общем `trades`-потоке позиция неизвестна, поэтому там честно показывается `Н/Д`; точные `LONG/SHORT` и `ОТКРЫТИЕ/ЗАКРЫТИЕ` доступны для сохранённых адресов через `userFills`. Это не инвестиционный сигнал и не гарантия полноты: браузер должен оставаться открытым, а соединение периодически переподключается.

## Сервер Ubuntu (144.31.223.144)

Адрес панели: `https://144-31-223-144.sslip.io` (голый IP перенаправляет туда). Вход по коду, код спрашивается один раз на устройство, сессия 30 дней, после 3 неверных попыток вход блокируется на час.

На Linux автоторговлю выполняет `autotrade.py` (перенос `autotrade.ps1`, правила те же):

- `push-server.js` держит один WebSocket к Hyperliquid, слушает адреса автоторговли и watchlist и передаёт каждую новую сделку в `server.py`;
- сервер сам перечитывает позиции всех лидеров и решает: открыть, закрыть или пропустить. Браузер можно закрыть;
- сигналы обрабатываются по одному, повтор той же сделки в течение 10 секунд не отправляется;
- ордера по умолчанию лимитные по текущей цене: post-only по лучшей цене стакана (комиссия мейкера), до 15 секунд переставляется за ценой, остаток добирается IOC-лимитом по текущей лучшей цене, без проскальзывания вглубь стакана. Вход отменяется, если цена ушла больше чем на 0.5%. Закрытие доводится до конца: что не взял стакан, закрывается по рынку. В панели можно переключить на рыночные;
- ключи Bybit хранятся в `data/autotrade.json` (права 0600, наружу не отдаётся), в интерфейсе видны только последние 4 символа;
- журнал решений: `data/autotrade-log.jsonl` и `GET /autotrade/log`.

Telegram: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `/etc/hyperliquid-radar.env`. Несколько получателей указываются через запятую, каждый получает все сообщения. Бот присылает сделки и ошибки автоторговли и открытия/закрытия отслеживаемых адресов (не чаще раза в минуту на адрес и монету). Команда `/status` в боте показывает состояние. Перед первым сообщением владелец должен нажать Start в боте.

Установка на чистый сервер: `RADAR_PASSWORD=... ./deploy-ubuntu.sh`, затем `./enable-https.sh`.
